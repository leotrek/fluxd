Three ideas worth keeping.

01 — MEMORY

Stream the data. Reuse the space.

Acquisition length does not determine codec workspace. Keep only the previous rows and entropy state needed by the supported predictor.

Read→Encode→Reuse buffer
02 — RELIABILITY

Incomplete data stays private.

Write to a temporary transaction, synchronize payload and metadata, then publish atomically. On restart, recover and verify before serving READY data.

Temporary→Sync→READY
03 — SEPARATION

The application is your choice.

The Unix socket API is independent of the application runtime. The consumer receives compressed bytes, decompresses them with the matching codec, and verifies the restored samples before processing. fluxd does not launch applications or containers.

List→Open→Decompress→Verify / use→Release

What is actually supported? Native Go CCSDS 123.0-B-1 subset: reduced P=0 column prediction, sample-adaptive lossless coding, 8/10/12/14/16-bit signed or unsigned samples, BSQ/BIL/BIP. Local tests and 60 predictor/entropy reference fixtures pass. Full-file decoder interoperability is still unverified. No general standards-compliance or flight-qualification claim is made. Identity and deflate are explicit development alternatives.
